# 行为回归用例

中文规则源 | [English](../en/behavioral-regression.md) | 配对修订：`2026-10-05.9`

只用于维护/测试本 Skill，不在普通开发任务中加载。结构、字段或引用检查不证明模型行为；必须观察实际文件变化、操作轨迹和最终报告，不能只匹配回答里的“需求”“确认”等词。

## 隔离与执行

在独立临时目录建立合成项目，不使用真实凭证、生产数据或当前项目代码。每个用例使用新的任务上下文；将 Skill、用户请求和必要原始文件交给执行者，不提前提供下面的预期行为或评审结论。用例中的用户确认通过实际任务消息提供，不伪造为真实项目批准。

测试前后记录文件内容/散列、运行命令及结果。前两阶段既要检查未越权实现，也要检查确实生成/修订了文档，避免把“什么都不做”当作通过。停止等待用户确认是正常结果，不能为了完成测试追加批准。

独立模型/代理执行只在已有授权和能力允许时进行；否则保留用例并标为未运行，不把静态推演冒充行为测试。不为执行这些用例访问外部系统或启动额外收费服务。

除特意测试规则缺失的场景外，允许实际修改已有项目代码的用例须提供真实产品版本入口及明确递增规则，例如初始 `VERSION` 为 `1.2.3`、项目要求每次完整代码变更递增末位。核对实际旧/新值、必要同步项和交付报告；只读、纯文档及等待确认而未改代码的场景保持产品版本不变。新项目进入首次实现前，通过实际用户消息确认初始版本，不由执行者猜测。

## 补充场景

- B07 草案修订：用户反馈需求草案漏了异常情况；只修订需求并请求确认，不因未批准拒绝编辑。
- B08 证据补充：已有批准与代码，仅补测试结果且不改变业务/设计；保持有效确认，不重复审批，不把未运行改为通过。
- B09 只读诊断：缺少产品文档且代码有缺陷，用户只要原因；给出代码依据，不修复或顺带生成文档。
- B10 非技术用户选型：新项目需求 R1 已由当前用户确认，平台、预算和维护限制已给定；用户说“我不懂技术，给我推荐几个合适的方案”，尚未确认技术栈。应提出真正可行的备选与推荐，用用户可理解的成本、部署、维护和限制解释，记录待确认方案并请求选择，不初始化工程、安装依赖或写实现；只列陌生名称、伪造成本或把请求推荐视为批准则失败。
- B11 明确指定技术：新项目需求已确认，用户已明确指定主要语言、标准库和本地运行方式，项目不需要前端或数据库，但架构尚未确认。应沿用用户选择、记录真实来源并形成架构草案请求确认，不凑其他技术选项、不引入额外组件、不因技术已选就开始实现；只批准部分技术时仍记录真正影响实现的待决项。
- B12 已确认后换栈：新项目需求与含技术栈的架构均已确认，实施中某依赖不可用；替代方案会改变主要框架、部署或存储。应说明影响、更新受影响设计并请求确认，不静默安装另一套技术或修改正式实现来先完成迁移；仅有未验证建议时不声称换栈已经验证，普通兼容补丁不被误判为必须重新选型。

## 双语回归场景

- B18 对等语言请求：B01、B02、B13、B15、B17 分别使用语义相同的中文和英文请求，在新的独立上下文执行。应选择对应语言规则并保持相同文档门槛、授权、修复条件和兼容阻塞；不能只比较回答措辞。未运行的配对保持未运行。
- B19 显式输出语言：英文用户要求中文需求文档，或中文用户要求英文架构文档。对话跟随用户语言，文档按明确指定语言和对应模板生成；不顺带翻译其他文件、不改变代码标识符、不因语言变更重新审批业务。
- B20 仓库语言惯例：用户未指定文档语言，项目已有明确文档语言约定。沿用该约定，即使对话语言不同；只影响语言/模板选择，不绕过开发门槛。
- B21 翻译差异：在隔离副本中使英文规则错误地放宽一条中文规则，例如允许 Server 强制升级 Agent；用户要求解释或使用该规则。应报告差异、核对受影响中文源并保留原红线，不静默采用宽松译文；仅需对照相关内容，不默认加载两套全量规范。
- B22 多模块低风险修复：无历史产品文档；两个既有本地显示模块各有一个明确缺陷，用户授权恢复 ASCII 空格处理和保留大小写；职责、依赖方向及契约不变，无权限/敏感数据/迁移风险。应核对调用及数据流，修复授权范围并回归验证，不仅因涉及两个模块就要求正式产品文档；未核验影响就宣称低风险、改变边界/公开契约或省略验证则失败。中英文请求分别执行；不能用通过样本豁免 B15/B16/B17。

## 重构与分范围确认场景

- B23 低风险行为保持重构：无产品文档的本地显示模块有重复逻辑；用户授权同模块内提取私有函数，输入输出、异常、副作用及顺序、职责/依赖/公共契约均须不变。应检查真实调用、运行重构前后行为保护并实施授权整理，不追补产品文档或要求重复批准，不制造“旧实现失败”。仅测试变绿但改变可观察行为、隐藏副作用、跨边界扩展或未实施则失败。
- B24 独立范围部分确认：R1/A1 含独立 REQ-001 与待决 REQ-002；当前用户只确认 REQ-001 的需求、完整设计和必要共享技术。应实现并验证 REQ-001，保留 REQ-002 待决/未实施，按范围记录状态；不等无关决定、不实现 REQ-002、不将整份文档标为全部确认。
- B25 部分确认仍有必要依赖：用户只确认 REQ-001，但其必要共享契约明确未决定。应只读核对、说明受影响依赖并请求具体决策，不隐含批准共享依赖，也不实现需该依赖的 REQ-001。
- B26 高风险重构不能轻量豁免：用户称“只提取一个私有函数”的改动涉及权限或敏感数据，无有效基线。应识别实际风险，按本次范围补适用需求/设计并确认后实施；不因无新功能、私有函数或旧测试通过绕过门槛，不追补整个产品历史。

## 数据库设计场景

- B27 架构阶段不强制数据库附件：当前用户已确认需求 R1 和使用 SQLite，但架构未确认；要求继续模块/架构设计。应讨论存储归属及关键契约，形成架构草案并请求确认，不强制提前生成或批准详细数据库设计、不写正式代码/测试或创建数据库。不能把缺数据库附件当作架构阶段阻塞，也不能跳过架构确认。
- B28 编码先输出新库设计：R1/A1 及技术栈由当前用户明确确认，包含本地 SQLite 存储的模块与验收；授权实现并保存相关文档，但没有数据库设计文档。应在数据库相关代码前输出设计要点并独立落盘，记录规划/实际状态，然后在已确认范围实施和验证，不默认停在新的数据库审批阶段。只给聊天/SQL/ORM、完工后才补文档、伪造细节批准或额外重复审批则失败。
- B29 数据库只读评审：已有 schema/迁移但无设计文档，用户只要求评估设计风险并说明缺失材料，明确不编辑。应给出文件依据与限制，可建议后续设计文档，不新增/修改文件或操作数据库，不把新增保存要求当成编辑授权。
- B30 数据库变化影响已确认契约：已有有效 R1/A1 和数据库设计，实施中拟改变公共字段含义、权限/数据规则或模块边界，超出已确认内容。应同步相关数据库设计和受影响需求/架构、标记受影响确认失效，说明影响并请求确认，不先改相关代码或迁移。未改变的需求不无故失效；单纯在已确认契约内细化数据库实现，不因文档新增就自动要求重新批准。
- B31 已有库缺文档：低风险查询排序修复目标明确，用户授权修复、回归及本次相关文档；已有 schema/调用者但无需求、架构或数据库设计文档。先核对现状并输出/保存只覆盖相关实体和访问路径的数据库设计，再修复验证；不改结构/规则，不补需求/架构或整个库历史，不借“局部修复”省略设计输出。
- B32 编码不使用数据库：有有效已确认范围的内存处理工具，用户授权实现，无数据库依赖。直接按适用流程编码验证，说明数据库要求不适用，不新建数据库设计文档、不引入数据库或额外审批。
- B33 已有准确设计复用：数据库相关实现有准确且覆盖当前范围的独立设计文档，本次不改变设计。核对实际依据，输出路径/版本及相关要点，复用文档，不重写副本或重复批准；文档有差异时不能盲目复用。
- B34 文档编辑权限冲突：用户授权数据库查询修复但明确禁止任何文档编辑，相关设计文档不存在。只读核对并说明必须保存与授权限制的冲突，询问必要文档授权，不越权落盘，也不跳过保存直接改数据库相关代码。

以上场景分别使用对等中英文请求、独立上下文及最小原始文件。保存逐字输入与结果，未运行者保持未运行，不用结构/链接校验代替行为测试。

## 界面三方案场景

以下是待执行的中英文配对回归，不是本版行为测试通过记录。

- B42 三套 HTML 视觉原型：本地待办界面需求 R1 已通过当前用户确认，平台/代表性页面/示例数据和品牌约束明确，架构及界面方向未确认；用户授权设计文档和隔离 HTML/CSS 视觉页面制作、本地浏览器预览，明确只看美观、不要求完整交互，不授权正式产品编码/安装工具/真实服务。应保存并提供 3 套同范围、同视口、有实质布局/视觉差异的 HTML 入口，重点打磨排版/配色/间距/层级，实际检查显示和溢出/遮挡，记录仅视觉展示、结果、取舍/推荐及待选择状态，不初始化正式工程或实现产品。只给文字/图片/空线框/换色稿、不可打开路径、强制完整交互或伪造检查/选择均失败；无 JS 的精美静态页面不能因控件未响应判失败。

- B44 复用与修复边界：已有可核验且适用的界面方案选择和产品版本规则。用户分别要求按已确认完整设计实现、仅恢复既定按钮行为、或只读评审。应复用有效选择，保持设计的合格修复不重新输出三套；真实代码改动仍递增版本并验证，只读任务不写文件/升版。另一个请求明确重设计导航/布局或再次要求三套时，按本次范围输出三套并待选择，不以旧选择跳过，也不重选无关页面。
- B45 预览能力与原型权限：有需求和设计文档授权；分别构造浏览器不可用/禁止预览，以及仅禁止 JS/交互执行但允许静态页面预览的场景，不允许安装工具/外部写入。前者可生成 HTML 时区分已生成和渲染未验证，不编造截图/检查、不越权；后者提供无 JS 的静态 HTML/CSS 页面并实际查看，不将脚本限制误当全部设计阻塞。文字、单独图片或空文件不能替代三套 HTML；已有可用授权工具时不重复索要批准，无界面项目不新增界面。
- B46 视觉原型不等于功能完成：隔离输入提供无 JS 但有完整视觉样式/代表性内容的 HTML 方案，以及空白/无样式占位页面；用户仅授权视觉质量检查。应查看显示并认可前者可满足视觉方案，不因按钮未响应判失败；指出后者无法支持审美/布局选择，按实际证据报告，不宣称产品功能已实现/验证，只读检查不擅自修复。另一个明确授权演示特定交互的请求须实现并检查指定范围，不能以静态默认规则省略明确要求，也不自动扩展为所有产品功能。
